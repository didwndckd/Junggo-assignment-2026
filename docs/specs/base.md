## 1. 요구 기술 스택
- 개발 도구: Xcode 26.5
- 언어: Swift 6
- 플랫폼/UI 프레임워크: iOS, SwiftUI
- 네트워크: 비동기 네트워크 처리 필수. 상품 원격 데이터는 DummyJSON Products API 사용.
  - 목록: `GET https://dummyjson.com/products`
  - 상세: `GET https://dummyjson.com/products/{id}`
- 상태 관리: 적절한 상태 관리 구조 적용 필요.
- 데이터 책임: 원격 데이터와 로컬 데이터의 책임을 구분하여 설계.
- 로컬 데이터: 찜 상태는 서버 API 없이 로컬에서 관리하며, 앱 재실행 후에도 유지.
- 외부 라이브러리 및 의존성 관리 방식: 자유. 사용 시 선택 이유를 Pull Request에 설명.
- iOS Deployment Target: 명시되지 않음.
- 빌드/실행: Repository clone 후 별도의 추가 작업 없이 빌드·실행 가능해야 함.

## 2. 요구 아키텍처 / 디자인 패턴
- 특정 아키텍처 패턴은 요구하지 않음. MVVM, MVI, Clean Architecture 등에서 과제 규모에 적합한 구조를 직접 선택.
- 프로젝트 구조와 기본 설정, 의존성 관리 방식은 과제 규모를 고려해 직접 구성.

## 3. 기능 목록
### 3.1 상품 목록
- 요약: DummyJSON Products API로 상품 목록을 표시한다.
- 동작:
  - 상품명, 가격, 상품 이미지, 찜 여부를 최소 정보로 노출한다.
  - 상품 선택 시 상품 상세 화면으로 이동한다.
  - 목록은 1열 리스트형 또는 2열 그리드형으로 표시할 수 있다.
- 우선순위: 필수

### 3.2 찜 상태 관리
- 요약: 상품을 찜하거나 찜 해제하고, 상태를 로컬에 영속화한다.
- 동작:
  - 찜 상태는 서버 API를 사용하지 않고 로컬에서 관리한다.
  - 앱 종료 후 재실행해도 찜 상태가 유지된다.
  - 목록과 상세 화면의 찜 상태가 일관되게 유지되고 서로 동기화된다.
- 우선순위: 필수

### 3.3 상품 상세
- 요약: 선택한 상품 ID로 상세 API를 호출해 주요 정보를 표시한다.
- 동작:
  - 상세 화면 진입 시 `GET https://dummyjson.com/products/{id}`를 호출한다.
  - 상품 주요 정보를 표시한다.
  - 찜 상태를 확인하고 변경할 수 있다.
- 우선순위: 필수

### 3.4 목록 보기 방식 전환
- 요약: 상품 목록 레이아웃을 1열 또는 2열로 전환한다.
- 동작:
  - 사용자의 선택에 따라 1열 리스트형 또는 2열 그리드형 레이아웃으로 변경한다.
  - 전환 후에도 상품명, 가격, 이미지, 찜 여부를 동일하게 표시한다.
- 우선순위: 필수

### 3.5 제출 및 Pull Request 문서화
- 요약: 생성한 Git Repository를 공유하고 Pull Request에서 설계 및 AI 활용 내역을 설명한다.
- 동작:
  - PR에 전체 프로젝트 구조, 주요 모듈/계층 책임, 프로젝트·의존성 구성 방식, 상태·데이터 흐름을 작성한다.
  - PR에 주요 기술적 판단과 추가 시간이 있을 때 개선하고 싶은 부분을 작성한다.
  - AI를 사용한 경우 도구, 활용 작업/질문, 결과 사용·수정 여부, 검증 방법을 작성한다. 미사용 시 미사용 사실을 작성한다.
- 우선순위: 필수

## 4. 추가 고려사항 / 예상 이슈
### 추가 고려사항
- 과제 수행 시간은 1일이며, 과도한 기능 추가나 UI 완성도보다 요구사항 해석과 구현·설계에 집중한다.
- 별도 초기 프로젝트나 Git 저장소가 제공되지 않으므로, 새 iOS 프로젝트와 Git Repository를 직접 생성한다.
- 상세 화면의 “주요 정보”에 포함할 구체 필드는 명시되지 않음.
- 보기 방식 선택값의 앱 재실행 후 유지 여부는 명시되지 않음.

### 예상 이슈
- 네트워크 요청 실패, 로딩 상태, 빈 데이터 상태에 대한 화면/재시도 동작은 명시되지 않음.
- 원격 상품 정보와 로컬 찜 상태를 상품 ID 기준으로 결합하고, 목록·상세 간 상태 일관성을 보장해야 함.
- 상품 이미지의 비동기 로딩 실패 처리 및 캐시 방식은 명시되지 않음.
